# VAD-OS Spark Monitor

Переносимый терминальный монитор Spark-машин, серверов моделей и статистики
ключей LiteLLM. Работает только пока запущен; по выходу закрывает свои SSH-туннели.

В программе **не записаны адреса кластера**. Она сама находит машины в вашем
tailnet через локальный клиент Tailscale и определяет запущенные серверы моделей.

## Требования

- Linux или macOS. На Windows используйте WSL.
- Tailscale, выполненный вход и доступ к тому же tailnet, где находятся Spark.
- SSH-доступ к Spark; по умолчанию пользователь `nvidia`.
- Python 3.10+ с модулем `curses` — только для Linux-варианта `.pyz`.
- Ключ LiteLLM с доступом к статистике.

Проверка Python на Linux/macOS:

```bash
python3 -c "import curses; print('OK')"
```

## Установка одной командой

На Linux и macOS с Python 3.10+ можно установить или обновить монитор одной
командой:

```bash
curl -fsSL https://raw.githubusercontent.com/FractalRainbowDot/vad-os-spark-monitor/main/install.sh | sh
```

Скрипт скачивает последний релиз с GitHub, проверяет SHA-256, устанавливает
`spark-monitor.pyz` в `~/.local/share/vad-os-spark-monitor` и создаёт исполняемый
лончер `~/.local/bin/spark-monitor`. Ключ `.env` хранится рядом с `.pyz` и при
обновлении не затрагивается. Скрипт можно сначала посмотреть:

```bash
curl -fsSL https://raw.githubusercontent.com/FractalRainbowDot/vad-os-spark-monitor/main/install.sh | less
```

Если `~/.local/bin` отсутствует в `PATH`, установщик добавляет блок в
`~/.bashrc`, `~/.zshrc` или `~/.profile` — в зависимости от текущей оболочки.
После установки откройте новый терминал или выполните `source` для нужного
файла. Чтобы не менять rc-файл, запустите установщик с
`SPARK_MONITOR_NO_PATH_UPDATE=1`.

После установки сохраните ключ и запустите монитор:

```bash
spark-monitor --save-key
spark-monitor
```

Если `~/.local/bin` отсутствует в `PATH`, скрипт покажет нужную строку
`export PATH=...`. Для macOS без Python используйте ZIP-сборку ниже.

## Установка и запуск

1. Сохраните `spark-monitor.pyz` в любую папку и откройте в ней терминал.
2. Один раз сохраните свой ключ LiteLLM (ввод скрытый):

   ```bash
   python3 spark-monitor.pyz --save-key
   ```

3. Запустите монитор:

   ```bash
   python3 spark-monitor.pyz
   ```

Внутри нажмите `l` для статистики LiteLLM. Флаги запуска не обязательны.

Ключ хранится в `.env` рядом с программой. **Не передавайте этот файл другим.**

## Mac с Apple Silicon (включая M5)

Python устанавливать не нужно. Распакуйте архив из `macos/` целиком и откройте
`Start Spark Monitor.command`. При первом запуске будет запрошен ключ.
Подробности — в `README-Mac.md` внутри архива.

## Автообнаружение

Монитор читает список машин из `tailscale status` и выбирает включённые Linux-машины,
имена которых подходят под шаблон `spark-*`. Для каждой найденной машины он:

- показывает GPU/RAM;
- ищет серверы vLLM/gb10 и embedding-модели, включая модели в контейнерах;
- создаёт SSH-туннель только к найденному HTTP-порту и обновляет карточку.

LiteLLM определяется по адресу порта `4000` на одной из Spark-машин.
Новые контейнеры появляются автоматически в течение 30 секунд; остановленные
помечаются, а не исчезают молча.

Карточки vLLM показывают «Вместимость» из `--max-num-seqs` и «Потоки процесса» —
число OS-потоков серверного процесса. Оба значения берутся тем же read-only
опросом, без записи на Spark.

Если ваши машины называются иначе:

```bash
python3 spark-monitor.pyz --spark-pattern 'gpu-node'
```

Если автоматический поиск не подходит, можно задать адреса вручную:

```bash
python3 spark-monitor.pyz --no-discovery --host SERVER_IP --remote-port 8000
```

Ручной режим требует явных адресов и не подходит для обычной работы.

## Обновления

При запуске монитор проверяет GitHub Releases. Если вышла новая версия, он
скачивает `spark-monitor.pyz`, проверяет SHA-256 и заменяет файл, сохраняя
резервную копию `.prev`. Ключ и `.env` не затрагиваются. Для применения
обновления перезапустите монитор или нажмите `[r]` в открытом окне.

Рядом с номером версии появляется значок `↑ vX.Y.Z` и строка с просьбой
перезапустить монитор. Значок остаётся видимым до перезапуска, поэтому
обновление не потеряется. Если релиз вышел во время работы, монитор повторяет
проверку раз в 5 минут и показывает значок без перезапуска. Если значка нет —
установлена последняя версия или проверка обновлений отключена.

```bash
python3 spark-monitor.pyz --check-update   # проверить и обновить сейчас
python3 spark-monitor.pyz --no-update-check
python3 spark-monitor.pyz --version
```

Автообновление работает только при запуске файла `.pyz`. Сборка macOS обновляет
встроенный `.pyz`; встроенный Python не заменяется.

## Права LiteLLM

LiteLLM автоматически показывает все доступные ключи администратору или только
текущий ключ обычному пользователю. Ключу должно быть разрешено чтение статистики;
ключи только для вызовов моделей (`llm_api_routes`) этого доступа не дают.

Если появляется 403, администратору нужно сохранить в **Virtual Keys → Edit →
Allowed Routes**:

```text
llm_api_routes, /user/info, /key/info, /user/daily/activity/aggregated, /model/info
```

`/model/info` нужен, чтобы обычный ключ видел настройки провайдера на вкладке
**ПРОВАЙДЕРЫ** окна `s`; без него там будет ошибка доступа. Если сервер отвечает
404, монитор пробует `/v1/model/info`.

Повышать роль пользователя до администратора для личной статистики не нужно.

## Короткая команда (необязательно)

В Bash/Zsh, находясь в папке с `.pyz`:

```bash
python3 - <<'PY'
from pathlib import Path
import shlex
p = Path('spark-monitor.pyz').resolve(strict=True)
f = Path.home() / '.local/bin/spark-monitor'
f.parent.mkdir(parents=True, exist_ok=True)
with f.open('x') as s:
    s.write('#!/bin/sh\nexec python3 ' + shlex.quote(str(p)) + ' "$@"\n')
f.chmod(0o755)
PY
export PATH="$HOME/.local/bin:$PATH"
```

Теперь запуск: `spark-monitor`. Если `~/.local/bin` не был в `PATH`, добавьте
строку `export` выше в `~/.bashrc` или `~/.zshrc`.

Удалить короткую команду (монитор и ключ останутся):

```bash
rm -- "$HOME/.local/bin/spark-monitor"
```

## Static: статичные настройки

Клавиша `s` открывает отдельное окно **Static** на вкладке **ПРОВАЙДЕРЫ**.
В окне две вкладки: `Tab` переключает их, `s` закрывает окно.

- **ПРОВАЙДЕРЫ** — маршруты и параметры LiteLLM из `/model/info`: маршрут,
  провайдер, upstream-модель, `api_base`, лимиты входа/выхода, RPM/TPM,
  стоимость за 1M токенов, флаги доступа и блокировки, а также все параметры
  провайдера.
- **SPARK** — статичная конфигурация запущенных моделей на каждом Spark: модель,
  движок, путь, контейнер/образ, время запуска, TP/PP и rank, контекст, лимиты,
  KV-cache, dtype, speculative и parsers, а также все флаги запуска.

Секреты провайдеров отображаются как `<скрыто>`, секреты в аргументах Spark —
как `<REDACTED>`. Настройки читаются по SSH из метаданных контейнеров и
командных строк процессов, обновляются раз в минуту. Переменные окружения не
читаются, секреты в аргументах скрываются. Модели без API тоже видны, если их
процесс запущен на Spark.

```bash
python3 spark-monitor.pyz --settings          # сразу открыть Static на вкладке провайдеров
python3 spark-monitor.pyz --once --settings   # один снимок обеих вкладок Static
```

## Настройки интерфейса

Клавиша `m` открывает всплывающее меню. Сейчас там два пункта; меню рассчитано
на добавление будущих настроек.

- **Тема** — 5 исходных и 34 темы OpenCode; `←`/`→` меняют палитру,
  `Enter` переключает на следующую.
- **Имя в шапке** — по умолчанию показывается alias текущего ключа LiteLLM из
  `/key/info` (например, `team-key`). Можно задать своё имя, например `VAD-OS`;
  пустое значение возвращает имя ключа. Русские буквы рисуются блочным шрифтом;
  длинные и неподдерживаемые имена выводятся обычным текстом.

Настройки хранятся в `.spark-monitor.json` рядом с `.pyz` с правами `600` и
переживают обновление. Это не секрет и не `.env`; файл не входит в релиз.

## Управление

| Клавиша | Действие |
|---|---|
| `v` | Модели и метрики (обычные модели) |
| `l` | LiteLLM / модели; активный LiteLLM подсвечивается в панели |
| `s` | Static: вкладки провайдеров и Spark |
| `m` | Меню темы и имени в шапке |
| `Tab` | Static: провайдеры / Spark; в моделях: обычные / embedding; в LiteLLM не действует |
| `j` / `k`, `[` / `]` в моделях | Выбрать карточку и переместить её вверх/вниз; порядок сохраняется |
| `r` | Перезапустить монитор после установленного обновления |
| `h` | Показать / скрыть пояснения |
| `-` | Обновлять реже |
| `=` / `+` | Обновлять чаще |
| `1`–`4` в LiteLLM | 1 день, 7 дней, 30 дней, год |
| Стрелки / PgUp / PgDn | Прокрутка |
| `q` / Ctrl+C | Выход |

Нижняя панель разделена на две строки: навигация по экранам и действия.
Текущее активное окно выделено подсветкой в цвете темы. `[-/+]` находится
в строке статуса рядом с временем и интервалом. GPU/RAM опрашиваются не чаще
раза в 5 секунд, LiteLLM — раз в минуту. Карточка без свежих данных дольше
180 секунд удаляется; её место в порядке сохраняется.
Периоды LiteLLM — календарные дни UTC, не скользящие 24 часа.
Ключи `key-hash…` и безымянные ключи исключены из таблицы и итогов.
